### Production verification

The entire HTTP/SSE suite was rerun against `https://hangd-party.ludvighedin.chatgpt.site` using the platform's supported private service access. It passed all 15 checks, including a complete two-round match, majority rematch, actual 20-second host inactivity, reconnection and cross-client secrecy. No public permissions were changed for the test. One SSE update was observed after 641 ms; this is a single sample, not a latency benchmark. The temporary access wrapper and its credentials are not part of this repository.

The production screenshot in `docs/screenshots/hangd-desktop.jpg` was generated by the deployment service and visually inspected. The anonymous browser visit correctly showed the current private-access sign-in gate. Public access still requires the owner's approval.

### Interactive browser observations

Room creation, joining through an invite URL, lobby settings, chat synchronization, starting a match, Word Master custom-word submission, countdown and the guesser view were exercised through the visible UI. A correct letter earned 10 points; an incorrect letter advanced the mascot's mistake count. KAOS reordered the other player's keyboard and then restored it. Refreshing the page restored the player identity and score from the server. A stalled word selection automatically advanced with a curated word.

The landing page and lobby were also used at mobile width. The room-creation form, roster and settings rendered without horizontal overflow. This was a responsive desktop-browser check, not a physical-phone test.

The shared managed preview was repeatedly stopped or replaced by unrelated projects during this session. As a result, the browser sequence through final results/rematch and a clean, uninterrupted console audit were not completed. Those game transitions did pass the HTTP/SSE integration suite. No browser failure caused by the replaced preview is being recorded as a successful HÄNGD check.

### Network flows exercised

The integration run used real HTTP requests and an independently consumed SSE stream. It verified:

- Room creation and joining with separate credentials.
- Rejection of duplicate nicknames, invalid/missing rooms, missing/forged credentials and credentials from another room.
- Host settings, Word Master submission and matching server deadlines across clients.
- Secret answers and other players' full-word guesses omitted from guessers' payloads.
- Correct and wrong letter synchronization, point awards and simultaneous duplicate guesses scoring only once.
- Full-word cooldowns, sabotage ownership/cooldowns and effects visible to opponents.
- Late arrival spectating and identity/score recovery using a saved token.
- Chat, reactions and typing indicators reaching another client.
- Hidden bluff truth, unique votes, private solves and intentional answer disclosure at results.
- A complete two-round match, master rotation, late-player participation, final results and majority rematch.
- Host transfer after actual 20-second inactivity, credential-based reconnection and transfer on explicit host departure.

One correct-letter update was observed in another client's SSE stream after **68 ms** in this local run. This is a single observation, **not a benchmark, average or production latency claim**. The server checks for updates every 450 ms; a request can arrive just before the next check. Network and database conditions change the result.

## Reproduce

Follow the root [README](../README.md) to install dependencies, build once and apply the local migration. From the project root:

```sh
pnpm check
pnpm test
pnpm build
```

Start a local server with `pnpm dev`, then run this in another terminal:

```sh
HANGD_TEST_URL=http://localhost:5173 pnpm test:integration
```

The managed preview uses port 4173; set `HANGD_TEST_URL` to that server when testing there. The suite creates rooms and sends real actions, so use a test database/deployment.

For a packaging check after creating the README's `wrangler.deploy.json`:

```sh
pnpm exec wrangler deploy --dry-run --config wrangler.deploy.json
```

This command does not publish the Worker or prove remote database connectivity. After an actual deployment, check `/api/health`, create a fresh room and complete a match through its invite link with separate devices. Record the tested origin, browser/device details and actual outcomes when those checks are executed.
