# Play-test and fix round, 23 October 2026

Owner request (Ludvig, 23 Oct): every game playable on phone and computer, no bugs, worth playing for more than 5 minutes, more games multiplayer, multiplayer that works, tested by us in a browser, slogans and micro copy removed, tidier UI, no overflow.

## What "done" means for each game

1. Loads with no console errors on desktop (1280x800, mouse + keyboard) and phone (390x844 and 320x640, touch, `isMobile`, `hasTouch`).
2. A real run works with real input on both: start, play, lose or win, restart. Pause/resume if the game has it. No softlocks, no stuck screens, no NaN/undefined in the UI.
3. No horizontal scroll and nothing clipped at 320, 390 and 1280 widths (check `document.documentElement.scrollWidth <= innerWidth` and look at screenshots). HUD does not cover the play area or the notch zone. Tap targets at least 44 px. No keyboard hints on touch screens.
4. Worth 5+ minutes: the game keeps giving something new (levels, difficulty ramp, unlocks, endless mode, goals). If it runs out in under 5 minutes or plateaus, add depth inside the game's existing style. Check long runs in code too: no growing arrays, leaks, or difficulty that becomes impossible or trivially easy.
5. Copy: follow `docs/calm-ui.md`. Delete slogans, taglines, eyebrow/kicker lines, jokey footers, commentary toasts, version stamps, repeated hints. Keep the title, one short functional start line at most, buttons, needed status and instructions. Do NOT rename games, change titles/wordmarks or in-world signs (owner decision pending). Gameplay jokes stay.
6. Multiplayer games: two separate players (two browser contexts) can play together through quick match, private code and invite link. Positions/state sync, a player leaving is handled, host handover works, wrong code gives a clear message. Single-player still works with no network.

## New multiplayer

Where your brief names candidates, add online play with `Ludvig.mp` (see `docs/platform-api.md`): quick match + private code + invite link `?<slug>=CODE` or the game's existing pattern, host (oldest peer) owns shared events, at most 10–12 messages per second per client, small payloads, interpolate remote players. ## How to test

- Local server: http://127.0.0.1:4317/<slug>/ (already running; do not start or stop servers). It serves `public/`, plus a local in-memory copy of the multiplayer relay at `/mp/ws` and stub score APIs.
- After editing `source-games/<slug>/`, refresh only your game into `public/`: `cd ludvig-games && python3 build.py --only <slug> [<slug> ...]`. Never run a full `python3 build.py` (it replaces `public/` while others test).
- Browser: use only `mcp__playwright__browser_run_code_unsafe`. Several agents share one Chrome, so inside every call create your own context and close it before returning:
  `const b = page.context().browser(); const c = await b.newContext({ viewport:{width:390,height:844}, hasTouch:true, isMobile:true, deviceScaleFactor:2 }); const p = await c.newPage(); ... await c.close();`
  Never use `browser_navigate`, `browser_click`, `browser_snapshot` or other tools that drive the shared page. State does not persist between calls, so do a whole scenario per call. Keep each call under about 2 minutes. Use touch with `p.touchscreen.tap(x,y)` or dispatched touch/pointer events; keyboard with `p.keyboard`.
- For two-player tests, make two contexts in the same call (separate storage, so separate player ids).
- Screenshots: `/private/tmp/claude-501/qa-round3/<slug>-<what>.png`. Look at them (Read tool) for overflow and clutter. Delete them when your game is done.
- Parse-check every changed script: `node --max-old-space-size=768 --check file.js` (or vm for inline scripts).

## Rules

- Edit only your assigned `source-games/<slug>/` folders (or your assigned external game folder). Never edit `games.json`, `scores.json`, `build.py`, `assets/`, `worker/`, `scripts/`, docs other than this one, or other games.
- Back up each file before the first edit to `ludvig-games/output/backups/2026-10-23-round3/<slug>/`.
- Keep save keys and storage formats. Keep performance phone-friendly (DPR cap 2, no per-frame allocations that grow).
- No npm installs, no wrangler, no deploys, no git. Do not pass any owner-authorization flag to a guard. If disk space errors appear, stop and report.
- Report under 350 words: per game one line on what was wrong and what you fixed, which games got multiplayer and how it was tested, the `players` text for games.json if it changed (e.g. "1–4 players"), and anything still broken. Separate what you saw in the browser from what you only read in code.
